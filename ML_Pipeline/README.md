# ML_Pipeline — Cryptocurrency Fraud Detection Pipeline

This is the necessary output for the dissertation "Cryptocurrency Scam Hotspots: Predictive Risk Modelling of Digital Platforms and Investor Exposure." It trains and assesses a Logistic Regression and a Random Forest classifier on two public, labeled blockchain datasets, specifically the Elliptic Bitcoin transaction graph and the Ethereum Fraud Detection Dataset, transforming each dataset's Random Forest predictions into a 0–1 risk score categorized as Low / Medium / High.

## Setup

```bash
pip install -r requirements.txt
```

## Folder structure

```text
ML_Pipeline/
├── Raw_data/          <- original Elliptic and Ethereum source files (input)
├── notebooks/          <- 01_Data_Import.ipynb - 08_Risk_Score.ipynb
├── cleaned_data/       <- output of 02_Data_Cleaning.ipynb
├── train_test_data/    <- output of 04_Feature_Engineering.ipynb
├── models/              <- trained .joblib models, scalers, and results.json
├── results/              <- risk_scores_elliptic.csv, risk_scores_ethereum.csv
└── eda_charts/           <- charts referenced in Chapters 4 and 6
```

`cleaned_data/`, `train_test_data/`, `models/`, `results/`, and `eda_charts/`
are all generated by running the notebooks below — none of them need to exist
beforehand, only `Raw_data/` does.

## Running the pipeline

Run the eight notebooks in order. Each one takes the previous stage's
output as input, so later notebooks will fail if an earlier one hasn't been
run yet.

| #  | Notebook                       | What it does                                                                                | Main output                 |
| -- | ------------------------------ | ------------------------------------------------------------------------------------------- | --------------------------- |
| 01 | `01_Data_Import.ipynb`         | Loads and checks the Elliptic and Ethereum datasets.                                        | Inspection only             |
| 02 | `02_Data_Cleaning.ipynb`       | Cleans the datasets, handles labels, removes duplicates and prepares the data for analysis. | `cleaned_data/*.csv`        |
| 03 | `03_EDA.ipynb`                 | Performs exploratory data analysis and creates charts.                                      | `eda_charts/*.png`          |
| 04 | `04_Feature_Engineering.ipynb` | Creates the training and testing datasets using the required data splits.                   | `train_test_data/*.csv`     |
| 05 | `05_Logistic_Regression.ipynb` | Trains the Logistic Regression model on both datasets.                                      | `models/lr_*.joblib`        |
| 06 | `06_Random_Forest.ipynb`       | Trains the Random Forest model on both datasets.                                            | `models/rf_*.joblib`        |
| 07 | `07_Model_Evaluation.ipynb`    | Evaluates the models and produces performance charts and feature-importance results.        | Model results and charts    |
| 08 | `08_Risk_Score.ipynb`          | Converts Random Forest predictions into risk scores and Low, Medium or High risk bands.     | `results/risk_scores_*.csv` |

## A note on runtime

`elliptic_txs_features.csv` (the unprocessed Elliptic feature file) is approximately 690MB. Specifically, `02_Data_Cleaning.ipynb` may take several minutes to execute on it, which is anticipated and not a freeze. The Ethereum part of the pipeline is significantly quicker overall because that dataset consists of a few thousand rows instead of hundreds of thousands.

## Verxia

The developed models and outcomes generated here are also utilized by `verxia_app/`, an additional web prototype that provides real-time predictions from these specific files. Refer to the root README in the repository and `verxia_app/README.md` for further information. The `verxia_app` is not a necessary part of this pipeline and can be disregarded if your aim is solely to replicate the dissertation results.
